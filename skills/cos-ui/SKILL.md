# cos-ui: generative UI in the panel

The panel renders a fenced ` ```cos-ui ` block as its own components, in the Chief's feed, in
agent chats, in Messages bubbles, and (when it's the last block of your reply) as your update card. Inside the block: **Markdown**, plus **component tags** from the catalog below. It
renders while you stream it, so write it top to bottom like normal text.

## When to use it (the default for anything with structure)

| Your result has… | Write |
|---|---|
| several items, numbers, steps, a comparison, a table, progress | **a cos-ui block**: a `Card` with the right components |
| work with steps that takes more than a minute or two (deploy, migration, audit, install) | **a live card** (`live_card`, below), updated as each step finishes |
| one question for Sandesh, a few answers, nothing else | a cos-card (see the cos-card skill) |
| finished, nothing to show beyond one sentence | a plain line, no block |

Pick the component for the shape of the data, not decoration:

- numbers → `Stat` (in a `Row`), with `change` for a before/after
- steps or a run → `Steps`, plus `Progress` when there's a fraction
- sizes, counts, costs per thing → `Chart type="bar"`; a trend over days → `Chart type="spark"`
- rows with several columns → `Table`; a few things, each with a status → `Grid` of `Card`s
- options to choose between → a `Grid` of `Card`s (one per option, the pros in a line) and a `Button` per option

Bad, a wall of text where the shape is the point:

```
Done. Freed 41 GB: Docker images 18.2 GB, Chrome clones 11.3 GB, Xcode caches 7.4 GB, npm 4.1 GB.
Free space is now 212 GB (was 171). I left ~/Movies (88 GB) alone.
```

Good, the same as a card:

````
```cos-ui
<Card title="machine-a disk: 41 GB freed" status="done">
<Row><Stat value="212 GB" label="free" change="+41"/><Stat value="0" label="files of yours touched"/></Row>
<Chart type="bar" unit="GB" data={[["Docker images", 18.2], ["Chrome clones", 11.3], ["Xcode caches", 7.4], ["npm cache", 4.1]]}/>
</Card>
```
````

Bad: a cos-card with a body paragraph and stats crammed into `stats` when the result has a list, steps or a
table. Bad: one message per step of a long job ("tests passed", "building", "deployed"): keep one live card.

## Live cards (work in progress)

For a job with steps, call the crew tool **`live_card(id, ui)`** at the start, then again **with the same
`id`** and the whole new version as each step finishes. `ui` is cos-ui source (no fence needed). The card
changes in place, in your chat and on your update card in Sandesh's feed; when your turn ends, its last
version stays as your update card (unless your reply ends with a block of its own). Don't also post the
steps as messages.

```
live_card(id="deploy", ui='''<Card title="Deploy cos (#143)" status="working" meta="machine-a">
<Progress value={3} max={5} label="Building the image"/>
<Steps items={[{text: "Tests", state: "done", note: "6m"}, {text: "Wait for the Chief to be idle", state: "done", note: "11m"},
  {text: "Build the image", state: "now"}, {text: "Restart and health check"}, {text: "Check desktop and phone"}]}/>
</Card>''')
```

The last call sets `status="done"` (or `error`, `needs`), marks every step, and adds the result (a `Stat`
row, a link). One live card per job; a second job gets its own id.

## Rules

- **Lean, calm.** Richer means structured, not busier: one card per reply, a handful of components, no
  decoration, no emoji. If a sentence says it, write the sentence.
- **Real numbers only** in `Stat` / `Progress` (counts, money, sizes, durations), never words.
- **Headings: `#` at most once, prefer `##`/`###` or a Card title.** No giant headings.
- **Links go in `url` (Card), `href` or `space` (Link)**, not as raw URLs in text. `space="<pack>:<page>"`
  opens a pack page inside the panel (e.g. `demo:money`, `demo:habits`).
- **Buttons only send a message**: `send="…"` goes to the chat the block is in (your own; the Chief's in
  the Chief's chat) as if Sandesh typed it; add
  `thread="<machine>:<chat id>"` to send it into that agent's chat instead. Write `send` as the full
  instruction. Buttons never approve, pay or send anything on his behalf by themselves. The button shows
  its label only (the message is in its tooltip), so make the label a clear answer. `thread` reaches
  only the chat the block is in, the Chief, or a group's lead (the Chief's own blocks: any agent).
- **Props are literals** (`"text"`, `{42}`, `{true}`, `{["a","b"]}`, `{[{text: "x", done: true}]}`)
  **or a small expression** over the block's state (`{seats * 49}`, see below). No functions, no
  JavaScript. Anything not in the catalog is dropped (he sees "n parts skipped").
- **Images**: only `https://artifacts.kingdomofluna.com/…` URLs, cptr files (`api/file/<node>/<file>`), or a
  screenshot you were shown, by its path (`/private/tmp/claude-…/<session>/images/<n>.png`).
- **Code inside the block**: open the block with **four** backticks (` ````cos-ui ` … ` ```` `); then
  ` ``` ` code fences inside it are fine. With three, a ` ``` ` line would close the block.
- Self-closing components (`Stat`, `Progress`, `Steps`, `Chart`, `Table`, `Checklist`, `Image`, `Divider`) end with `/>`.

## State, expressions, inputs and forms

The block can hold a little state that the owner changes on the spot (no model call, nothing sent
until he presses a button):

- **Declare** it once, near the top: `<State extra={0} city="" fast={true}/>`. Values are literals:
  a number, `"text"`, `true`/`false`. Names: letters, digits, `_`.
- **Bind** an input to it: `<Slider bind="extra" …/>`. An input bound to a name you didn't declare
  starts at its default (Slider: `min`, Toggle: off, Select: the first option, TextInput: empty).
- **Use** it in `{…}`: in text (`You'd pay **{fmt.money(4750 + extra)}**`), in a prop
  (`<Stat value={fmt.money(4750 + extra)}/>`, `<Show when={extra > 0}>`), and inside quoted text
  props (`label="Total for {nights} nights"`, `send="Pay {fmt.money(extra)} extra"`). Links (`href`,
  `url`, `src`, `space`) and `thread` never take `{…}`.
- **The expression language** is deliberately tiny: numbers, `"strings"`, `true`/`false`, state names,
  `+ - * / %`, `< <= > >= == !=`, `&& || !`, `cond ? a : b`, `( )`, and these helpers only:
  `fmt.money(n)` → $1,250 · `fmt.num(n, digits?)` → 1,250.5 · `fmt.pct(0.25)` → 25% (takes a
  fraction) · `round(n, digits?)` · `min(a, b, …)` · `max(a, b, …)`. No `a.b`, no other functions, no
  assignments. A name the block doesn't declare shows as empty and is reported. Write `\{` for a
  literal brace in text.
- **Arrays stay literal**: `Table` rows, `List` items, `Checklist` items and `Select` options can't be
  expressions.
- **Buttons with `{…}` in `send`** send the text as filled in at the moment he presses.
- **A Form** is a message template: `<Form send="Plan a {nights}-night trip to {city}">` with inputs
  inside and a `<Button>` **without** `send` as its submit. The template is filled with the values as
  plain text and sent to the chat the block is in (or with `thread="…"`, into that agent's chat) only when he presses
  the button. `required` on a TextInput keeps the button off until it's filled. A form never sends
  by itself.
- **Tabs**: `<Tabs><Tab label="This week">…</Tab><Tab label="Next week">…</Tab></Tabs>`. Add
  `bind="week"` to use the chosen label in expressions (`{week == "This week" ? … : …}`).
- Keep it small: one or two inputs that change numbers he cares about, or a short form whose message
  you'd otherwise ask him to type.

## Live data: agents and packs

Some components draw **live data** instead of what you write: never copy numbers or states into a
block when a live component shows them.

- **`<Agent id="machine-a:5dad2d83"/>`**: one agent's card as the board shows it (name, Needs you /
  Working / Stalled / Done, what it's doing, when). It changes as the agent does. `note="…"` replaces
  the "what it's doing" line.
- **`<Agents filter="needs" limit={3}/>`**: the board's own list: `needs` (waiting for him), `running`
  (working or stalled), `open` (finished, tab still open), `all` (the three, needs first; default).
  The Chief's own chats are never listed. Empty is fine: "Nothing needs you" is news.
- **`<Screen machine="aibo-linux"/>`**: a live picture of that machine's screen, with what you're doing
  and Watch / Take over / Hand back for him. It plays only while you share the screen (`share_screen`;
  your chat shows a card by itself then, so don't add one to every reply). Put one in a reply when the
  picture says it better than words, for example when you ask him to type a code on the page you're on.
  You never see its picture and he decides whether to take over; `note="…"` is the line it shows while
  nobody shares.
- **Pack components**: `<pack.Name …/>`. Each pack declares its own; this instance has:

  (none on this instance)

  The hub fetches the data (read only, cached under a minute); the panel draws it as a checklist,
  list, table or stat row with a link to the pack's page. Every one takes `title="…"`, `limit={n}`,
  and (when it has done/not done) `hideDone`. Args are checked: an unknown arg or a wrong type is
  skipped and noted.
- Args may be `{expressions}` over the block's state: `<Slider bind="days" …/>` +
  `<demo.Bills days={days}/>` refetches as he moves it.
- While loading it shows a quiet placeholder; if the source is down: "Couldn't load …" with a retry.
  Nothing else to handle. Live components are self-closing (`/>`) and never take children.

## Mini apps (cos-app)

When the catalog can't do it (a small game, a simulator, a custom chart or interaction), write a
` ````cos-app ` block instead: a small self-contained HTML document (HTML + CSS + JS, inline) that the
panel runs in a locked box. **Only then**: anything the catalog can draw belongs in a cos-ui block.

`````
````cos-app
{"title": "Bouncy balls", "height": 360}
<canvas id="c"></canvas>
<script>/* … */</script>
````
`````

- **Open it with four backticks** (` ````cos-app ` … ` ```` `), so a ` ``` ` inside your JS can't end it.
- **Header** (optional, first line): `{"title": "…", "height": 120–900 (px, default 320) or "auto", "aspect": "16:9"}`.
  `"auto"` sizes the box to your content.
- **Self-contained: use no network.** No fetch/XHR/WebSocket, no outside scripts, styles, fonts or images
  (its content policy blocks them); images as `data:` URLs. **Put the data inline** in the script. It can't
  read cos, the owner's data or cookies, and it can't open windows or submit forms. If it navigates its own
  frame, the panel stops it, but only after that first request has gone out: the sandbox limits what an app
  can reach, it isn't a promise that nothing leaves. It's sandboxed: `localStorage` throws, so keep state in variables.
- **Keep it small**: a few KB to tens of KB (the hard cap is 200 KB). Phone first: it's often 360 px wide.
- **Theme**: CSS variables `--cos-bg`, `--cos-surface`, `--cos-ink`, `--cos-ink-2`, `--cos-ink-3`, `--cos-line`,
  `--cos-accent`, `--cos-accent-bg`, `--cos-accent-ink`, `--cos-pos`, `--cos-warn`, `--cos-neg`, `--cos-blue`,
  `--cos-font`, `--cos-radius` (they carry Sandesh's chosen colour theme); `cos.theme` is `"light"`/`"dark"`,
  `cos.palette` the theme's name, and a `cos-theme` event fires on a switch of either (re-read the variables then).
- **The `cos` helper**: `cos.resize(px)` / `cos.fit()` (resize the box to the content), and
  `cos.send("…")`: suggests a message for the chat the app is in. Sandesh sees the exact text, a tap
  puts it in the message box, and he sends it himself; it's never sent by itself. Write it as the full instruction.
- It runs only after Sandesh taps **Run** once for it, and never while you're still writing it.
